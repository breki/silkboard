# implement

Read the task, current Git state, roadmap, and relevant source. Verify factual
claims before choosing an approach. If no task was supplied, ask which task;
do not pick a product milestone. Settle high-impact decisions with the owner.

For substantial work, keep a working document under `docs/issues/` using the
task slug: goal, agreed approach, acceptance checks, progress, and open facts.
Use plan mode constraints when active. Implement only the agreed scope using
[quality rules](../quality.md). Run targeted checks, self-review, and complete
appropriate validation. Update the captured item's status only with evidence.

At completion, move durable decisions to their source documents and remove
only the working document created for this completed task; preserve unfinished
work. Report remaining blockers. Commit, review, and release are separate;
do not invoke them merely because implementation ended.
