# backlog-report

Use authenticated read access to list all open GitHub issues in
`breki/silkboard` using pagination. GitHub is the authoritative backlog;
distinguish unavailable access from an empty backlog. Read linked local
implementation notes when useful, without treating them as separate backlog
items. Group by actual project area and distinguish recorded priority from a
suggested priority. Describe scope, dependencies, complexity, and what remains
unknown without inventing acceptance criteria.

Use [html-report](html-report.md) to produce a local table with source links,
status, and useful comparisons. Include collection time and any incomplete
source. Do not change implementation notes, issue bodies, labels, or priorities.
