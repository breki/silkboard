# retrospect

Skip routine documentation-only save points unless a retrospective is asked
for explicitly. Inspect the session and relevant workflow, not unrelated
history. Identify concrete observations under Efficiency, Quality, Speed, and
Cleanup; distinguish demonstrated problems from preferences.

Report the consequence and smallest useful change. Do not optimize away real
verification or the deliberately sequential review stages. Keep observations
with no durable value in the conversation. Promote agreed shared rules to
canon; capture substantive proposals as backlog items. Apply only corrections
within existing task authorization; do not silently expand the work or start
a new commit/review cycle. Reviewer findings stay in their own records.
